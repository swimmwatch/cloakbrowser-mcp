# Idea Refine

Turn an unclear direction into a decision-ready proposal.

1. Define the user or operator, problem, desired outcome, non-goals, constraints, and success signal.
2. Read only the relevant current code, docs, tests, and existing decisions. Identify assumptions that need validation.
3. Offer two to four materially different options, including the smallest experiment and a credible defer-or-remove option when appropriate.
4. Compare only material criteria: user value, MCP compatibility, security, maintenance cost, testing burden, Docker/package impact, documentation impact, and reversibility.
5. Recommend a direction, smallest validation step, and explicit decision needed from the user.

Do not turn ideation into implementation or claim feasibility without evidence.
