# Супастаўленне праз GeoIP-праксі

Супастаўленне проксі GeoIP дазваляе наладам адбітка пальцаў браўзера адпавядаць месцазнаходжанню проксі, якое выкарыстоўваецца верхнім MCP Playwright. Гэта карысна, калі рэгіянальнае забеспячэнне якасці залежыць ад паслядоўнага проксі, часавага пояса, мовы і профілю лакалі.

Мост сам не стварае і не маршрутызуе трафік праксі. Ён перадае
`PLAYWRIGHT_MCP_PROXY_SERVER` у падрыхтоўку запуску CloakBrowser. Калі
супастаўленне ўключана, CloakBrowser вызначае месца выхаду наладжанага праксі і
дадае адпаведныя сцягі запуску для часавага пояса, мовы браўзера, лакалі
адбітка і IP-адраса WebRTC.

## Што гэта мяняе

Калі `CLOAK_PLAYWRIGHT_MCP_GEOIP_PROXY_MATCH=true`, масток можа дадаць гэтыя сцягі запуску для CloakBrowser:

- `--fingerprint-timezone`
- `--lang`
- `--fingerprint-locale`
- `--fingerprint-webrtc-ip`

Гэта дапамагае профілю браўзера выглядаць унутрана сумяшчальным з рэгіёнам праксі-сервера.
Схемы інструмента Playwright MCP і інструменты браўзера ўсё яшчэ перадаюцца без змен.

## Сусветныя налады

Выкарыстоўвайце зменныя асяроддзя ўзроўню працэсу для кліентаў stdio і ў якасці стандартных для струменевых HTTP-сеансаў:

```bash
PLAYWRIGHT_MCP_PROXY_SERVER="http://user:pass@proxy.example:8080" \
CLOAK_PLAYWRIGHT_MCP_GEOIP_PROXY_MATCH=true \
npx -y cloakbrowser-mcp@latest
```

Дадайце спіс абыходу, калі некаторым хостам трэба абыходзіць праксі:

```bash
PLAYWRIGHT_MCP_PROXY_SERVER="http://user:pass@proxy.example:8080" \
PLAYWRIGHT_MCP_PROXY_BYPASS=".internal,localhost" \
CLOAK_PLAYWRIGHT_MCP_GEOIP_PROXY_MATCH=true \
npx -y cloakbrowser-mcp@latest
```

Аўтэнтыфікаваныя HTTP-праксі падтрымліваюцца шляхам убудавання ўліковых даных у
`PLAYWRIGHT_MCP_PROXY_SERVER`. Працэнтны кадаванне спецыяльных сімвалаў у пацвярджэннях,
напрыклад, выкарыстоўвайце `p%40ssword` для `p@ssword`.

Падтрымліваемыя бінарныя файлы CloakBrowser выкарыстоўваюць убудаваную
аўтэнтыфікацыю ў URL і паведамляюць сапраўдны IP-адрас выхаду праксі, нават калі
праксі патрабуе строгі аўтэнтыфікаваны запыт CONNECT. Старыя бінарныя файлы
захоўваюць аб'ект праксі Playwright як запасны варыянт сумяшчальнасці.

## Наладка Docker

Перадайце тыя ж зменныя кантэйнеру. Пры магчымасці захоўвайце праксі-пасведчанні ў вашым кіраўніку сакрэтаў або асяроддзі кліента MCP.

```bash
docker run --rm --init -i \
  -e PLAYWRIGHT_MCP_PROXY_SERVER="http://user:pass@proxy.example:8080" \
  -e CLOAK_PLAYWRIGHT_MCP_GEOIP_PROXY_MATCH=true \
  -v "$PWD/artifacts:/data" \
  swimmwatch/cloakbrowser-mcp:latest
```

Для Streamable HTTP у Docker апублікуйце HTTP-порт як звычайна і захавайце зменныя проксі як стандартныя для асяроддзя кантэйнера:

```bash
docker run --rm --init -p 127.0.0.1:3000:3000 \
  -e PLAYWRIGHT_MCP_PROXY_SERVER="http://user:pass@proxy.example:8080" \
  -e CLOAK_PLAYWRIGHT_MCP_GEOIP_PROXY_MATCH=true \
  -v "$PWD/artifacts:/data" \
  swimmwatch/cloakbrowser-mcp:latest \
  --transport streamable-http --http-host 0.0.0.0 --http-port 3000
```

## Струменевы HTTP-праксі на адну сесію

Патэкавыя HTTP-кліенты могуць выбраць праксі-сервер падчас ініцыялізацыі сеансу MCP. Гэта дазваляе аднаму доўгатэрміноваму серверу MCP апрацоўваць розныя рэгіянальныя сцэнарыі без перазапуску.

Дашліце метаданыя моста ў запыце `initialize`:

```json
{
  "params": {
    "_meta": {
      "io.github.swimmwatch/cloakbrowser-mcp": {
        "proxyServer": "http://user:pass@proxy.example:8080",
        "proxyBypass": ".internal,localhost",
        "geoipProxyMatch": true
      }
    }
  }
}
```

`proxyServer` перавызначае `PLAYWRIGHT_MCP_PROXY_SERVER` для гэтай HTTP-сесіі.
`proxyBypass` перавышае `PLAYWRIGHT_MCP_PROXY_BYPASS` толькі калі `proxyServer` існуе. Калі `proxyServer` існуе, а `proxyBypass` прапускаецца, наследаваная канфігурацыя абыходу проксі для гэтай сесіі ачышчаецца.

`geoipProxyMatch` перавызначае налады GeoIP на ўзроўні працэсу для гэтага HTTP-сеансу. Выкарыстоўвайце `true` для ўключэння супастаўлення для сеансу або `false` для яго адключэння, нават калі сервер быў запушчаны з уключаным супастаўленнем.

Існуючыя HTTP-сесіі незваротныя. Стварыце яшчэ адну Streamable HTTP-сесію, каб пераключыцца на іншы праксі-сервер або месцазнаходжанне.

Калі `proxyServer` змяшчае ўліковыя даныя, захоўвайце іх у URL-кодаванні і перадавайце значэнне праз сакрэты або канфігурацыю выканання кліента, замест таго каб убудоўваць яго ў файлы праекта.

## Прыярытэты і абмежаванні

| Вобласць | Паводзіны |
| --- | --- |
| Stdio | Выкарыстоўвае толькі зменныя асяроддзя і флагі CLI на ўзроўні працэсу. |
| Значэнне па змаўчанні Streamable HTTP | Выкарыстоўвае зменныя асяроддзя і флагі CLI на ўзроўні працэсу, калі метаданыя runtime не перададзены. |
| Метаданыя Streamable HTTP | `initialize.params._meta["io.github.swimmwatch/cloakbrowser-mcp"]` можа пераазначыць проксі і супастаўленне GeoIP для аднаго сеанса. |
| Існыя сеансы | Захоўваюць проксі і наладу GeoIP, зафіксаваныя падчас `initialize`. |
| Аўтэнтыфікаваны HTTP-праксі | Выкарыстоўвае ўбудаваную аўтэнтыфікацыю CloakBrowser у URL на падтрымліваемых бінарных файлах і аб'ект праксі Playwright на старых бінарных файлах. |
| Неапрацаваныя сцягі часавага пояса/лакалі | Яўныя значэнні `--fingerprint-timezone`, `--lang` і `--fingerprint-locale` у `CLOAK_PLAYWRIGHT_MCP_EXTRA_ARGS` маюць прыярытэт над значэннямі GeoIP і не дублююцца. |
| Browser geolocation API | Не наладжваецца гэтай функцыяй; яна толькі ўзгадняе значэнні адбітка часавага пояса, мовы, лакалі і IP-адраса WebRTC CloakBrowser. |

Даныя геалакацыі GeoIP з'яўляюцца прыблізнымі і залежаць ад IP-адраса праксі-сервера і базы даных GeoIP CloakBrowser. CloakBrowser спампоўвае і кэшуе гэту афлайн-базу даных пры першым выкарыстанні, калі яна патрэбна.

Напрыклад, наступная канфігурацыя захоўвае яўныя часавы пояс і лакаль, але
працягвае выкарыстоўваць супастаўленне GeoIP для вызначэння IP-адраса выхаду
праксі:

```bash
PLAYWRIGHT_MCP_PROXY_SERVER="http://user:pass@proxy.example:8080" \
CLOAK_PLAYWRIGHT_MCP_GEOIP_PROXY_MATCH=true \
CLOAK_PLAYWRIGHT_MCP_EXTRA_ARGS='["--fingerprint-timezone=America/New_York","--lang=en-US","--fingerprint-locale=en-US"]' \
npx -y cloakbrowser-mcp@latest
```

Выкарыстоўвайце гэту функцыю для законнага тэсціравання на якасць, лакалізацыю і сумяшчальнасць асяроддзя. Яе нельга разглядаць як спосаб абыходу кантролю доступу або праверкі рэгіянальнай палітыкі.
