# Поширені запитання

## Що таке CloakBrowser MCP?

CloakBrowser MCP — це сервер [Model Context Protocol](https://modelcontextprotocol.io/) для автоматизації роботи браузера через stdio або Streamable HTTP. Він працює вище за течією [`@playwright/mcp`](https://github.com/microsoft/playwright-mcp) та направляє конфігурацію запуску браузера Playwright MCP на бінарний файл [CloakBrowser](https://github.com/CloakHQ/CloakBrowser) на базі Chromium.

## Чим він відрізняється від вихідної версії Playwright MCP?

Сервер Playwright MCP, розташований вище за ланцюгом, відповідає за схеми, описи та відповіді інструментів браузера. CloakBrowser MCP залишає ці інструменти без змін і додає лише два локальні інструменти інтроспекції: `cloakbrowser_binary_info` та `cloakbrowser_bridge_info`.

## Чи варто встановлювати його через npm чи Docker?

Використовуйте npm, якщо на вашому комп’ютері вже запущено клієнт MCP і доступна Node.js 22.13 або новіша версія в гілці 22.x чи Node.js 24 або новіша. Використовуйте Docker, якщо вам потрібен відтворюваний образ на базі Playwright MCP із кешем CloakBrowser, підготовленим усередині контейнера.

## Які клієнти MCP можуть ним користуватися?

Будь-який клієнт MCP, що підтримує stdio або HTTP-сервери типу Streamable, може використовувати CloakBrowser MCP. Посібник [«Початок роботи»](getting-started.md) містить приклади JSON-даних для stdio, призначені для таких клієнтів, як Codex, Claude Desktop, Claude Code, Cursor, клієнти у стилі VS Code/Cline, Continue, Windsurf, Goose та конфігурації у стилі Warp.

## Чи підтримує він ті самі інструменти браузера, що й Playwright MCP?

Так. Браузерні інструменти Upstream Playwright MCP передаються без змін. У рамках проекту також виконується порівняння відповідності в системі безперервної інтеграції (CI), щоб зміни в мості можна було перевірити на відповідність офіційній поведінці Playwright MCP.

## Чи підвищує Docker рівень безпеки?

Docker забезпечує більш відтворюване та ізольоване середовище виконання, але це не робить автоматизацію роботи браузера повністю безпечною. Ставтеся до автоматизованого перегляду веб-сторінок як до ненадійного виконання: уникайте передачі конфіденційних даних невідомим веб-сторінкам, зберігайте артефакти та знімки екрана в контрольованих каталогах і ознайомтеся з посібником [«Безпека»](security.md), перш ніж підключати сервер до інших систем.

## Чи використовується в цьому проєкті аналітика або відстеження?

Ні. На сайті документації аналітика за замовчуванням не ввімкнена. Індексація пошуковими системами здійснюється за допомогою стандартних метаданих, `robots.txt`, формування карти сайту, опціональних тегів для підтвердження веб-майстра та опціональних сповіщень IndexNow.
