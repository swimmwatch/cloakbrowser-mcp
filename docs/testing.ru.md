# Тестирование

## Модульные тесты

```bash
npm run test:unit
```

Модульные тесты покрывают разбор переменных среды, генерацию конфигурации моста, обработку аргументов запуска и локальные инструменты интроспекции Cloak.

## Интеграционные тесты

```bash
npm run test:integration
```

Интеграционные тесты используют фальшивый дочерний процесс upstream MCP и проверяют, что мост объединяет локальные инструменты и пересылает upstream-вызовы без изменений.

`npm run check` включает статические проверки, unit/integration-тесты и тесты упакованного CLI с имитацией upstream MCP, без Chromium. В PR unit/integration и CLI запускаются один раз для каждой комбинации платформы и Node.js: {{ project.node_check_versions }} на Linux x64/arm64, macOS x64/arm64 и Windows x64. На Linux x64 тот же прогон собирает покрытие для Codecov. Статические проверки и проверка пакета выполняются один раз на Linux x64/Node.js {{ project.node_minimum_version }}.

Матрица CI, список ожидаемых результатов отчёта и документация получают версии Node.js из `.github/workflows/ci.yml`. Обновляйте этот файл при изменении проверяемых веток выпуска.

## Проверки настоящего браузера и дистрибутивов

```bash
npm run test:e2e
npm run test:e2e:playwright-console
npm run test:e2e:cdp
npm run test:e2e:npm-package
npm run test:e2e:docker
npm run test:e2e:cdp:docker
```

`test:e2e` объединяет проверки CLI с fake upstream и проверки консоли настоящего Playwright Chromium. `test:e2e:playwright-console` проверяет методы консоли в новых браузерных сеансах. `test:e2e:cdp` проверяет управляемый доступ через Chrome DevTools Protocol (CDP) с Free CloakBrowser и контролируемым Playwright Chromium.

`test:e2e:npm-package` упаковывает и устанавливает пакет во временный проект. Проверка контракта пересылки использует fake upstream; браузерные сценарии используют настоящий CloakBrowser и локальные страницы для проверки стандартных инструментов, постоянного состояния и обоих пресетов humanize. Отдельный тест проверяет конкурентные скачивания в пустой кэш и отсутствие постороннего текста в stdout. Одна проверка пакета не подтверждает работу браузера.

Браузерная PR-матрица проверяет консоль Playwright и управляемый CDP на Node.js {{ project.node_current_version }} на тех же пяти платформах; дополнительно CDP проверяется на Linux x64/Node.js {{ project.node_minimum_version }}. Параллельная матрица Node.js {{ project.node_primary_version }} запускает наборы npm-пакета, proxy/GeoIP, расширений и lifecycle на всех пяти платформах, включая оба пресета humanize. Приёмка Docker и CDP охватывает оба движка на `linux/amd64` и `linux/arm64`.

`required-ci` требует успешного завершения каждого набора и полного сводного отчёта до мержа. Тот же workflow `CI` запускается еженедельно и вручную. `Release` собирает и публикует артефакты из проверенной версии кода.

## Отчёты о тестировании

Каждая ячейка матрицы CI загружает очищенные результаты и диагностические вложения. Задача агрегации объединяет их в один HTML-отчёт Allure, сохраняя метки набора тестов и окружения. Отсутствие ожидаемых источников результатов и падения тестов приводят к ошибке агрегации; исходные результаты и HTML-отчёт остаются доступны как артефакты Actions.

Подходящие запуски PR могут публиковать ссылку на отчёт через настроенный отдельный репозиторий отчётов. Для публикации нужны включённая доставка, проверенные данные запуска и успешная проверка Pages. Сайт документации развёртывается отдельно. Публичные отчёты содержат только разрешённую и очищенную диагностику из контролируемых тестовых данных.

```bash
npm run test:report -- --suite unit --run-id local
npm run test:report:generate -- --input artifacts/test-results --output artifacts/test-report/local
npm run test:report:open -- --report artifacts/test-report/local
```

Используйте фактический выходной каталог сборщика как вход генератора. Форматы отчётов, вложения и доставка через CI описаны в разделе [Участие в разработке](contributing.md).

## Проверка пакета

```bash
npm run package:verify
```

Эта команда собирает пакет, запускает `npm pack`, проверяет список файлов tarball, устанавливает tarball во временный проект и проверяет `--version` и `--help` CLI.

Проверка пакета также валидирует `server.json` по опубликованной схеме MCP-сервера.

Для сборки релиза используется `npm run package:pack`: команда создаёт архив и проверяет метаданные и состав файлов. Установка пакета и выполнение CLI проверяются до мержа командой `package:verify`.

## Docker smoke-тест

```bash
npm run docker:build
npm run docker:smoke
```

Smoke-тест проверяет, что собранный образ запускается и выводит справку CLI. CI выполняет smoke-тесты Docker-образов для `linux/amd64` и `linux/arm64`.

## Совместимость с upstream

```bash
npm run bridge:compare
npm run bridge:compare -- cloakbrowser-mcp:dev --report bridge-parity-report.json
```

Скрипт совместимости запускает официальный Docker-образ Playwright MCP и образ моста CloakBrowser, сравнивает имена upstream-инструментов, выполняет стандартный набор браузерных инструментов на одной fixture-странице и проверяет локальные инструменты интроспекции Cloak.

CI загружает JSON-отчёт о соответствии из Docker jobs. Браузерное сравнение запускается на `linux/amd64`; на обеих архитектурах выполняются smoke-проверки, сканирование уязвимостей, тесты дистрибутива и CDP. Сравнение охватывает закреплённую версию Docker MCP; набор npm отдельно проверяет npm MCP.

## Проверки безопасности

```bash
npm run audit:prod
npm run server:validate
```

CI также запускает CodeQL, Dependency Review, OpenSSF Scorecard, zizmor и Trivy. Эти инструменты бесплатны для публичных репозиториев и не требуют внешних аккаунтов.
