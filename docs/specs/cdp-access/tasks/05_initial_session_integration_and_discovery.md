## Public Configuration Contract

- `--cdp-port-range <port|start-end>` / `CLOAK_PLAYWRIGHT_MCP_CDP_PORT_RANGE` configures the process-local external pool but never enables CDP by itself.
- `--cdp-enabled` / `CLOAK_PLAYWRIGHT_MCP_CDP_ENABLED=true` sets the process-level enabled default. The documented default is false.
- `--no-cdp-enabled` is explicit CLI false and overrides environment true. Positive and negative forms in one invocation fail.
- `--cdp-host <host>` / `CLOAK_PLAYWRIGHT_MCP_CDP_HOST` defaults to `127.0.0.1`.
- `--cdp-allow-remote` / `CLOAK_PLAYWRIGHT_MCP_CDP_ALLOW_REMOTE=true` defaults false and is required for a non-loopback bind.
- `--no-cdp-allow-remote` is explicit CLI false and overrides environment true. Positive and negative forms in one invocation fail.
- `--cdp-advertised-host <host>` / `CLOAK_PLAYWRIGHT_MCP_CDP_ADVERTISED_HOST` supplies connectable authority where required.
- `--cdp-advertised-scheme <http|https>` / `CLOAK_PLAYWRIGHT_MCP_CDP_ADVERTISED_SCHEME` defaults to `http`; it only selects `http/ws` or `https/wss` publication.
- CLI values override corresponding environment values per setting. Shadowed invalid environment values do not fail an otherwise valid effective configuration.
- All `CLOAK_PLAYWRIGHT_MCP_CDP_*` variables are consumed before building the child environment. Do not add `CLOAKBROWSER_MCP_*` aliases.

## Session Contract And Order

1. Parse and validate static process configuration before creating a listener or upstream child.
2. For stdio, use the process enabled default directly. Effective true requires a pool and creates one managed session; false creates no CDP resource.
3. For Streamable HTTP, accept only a flat boolean `cdpEnabled`. Absence inherits the process default; literal true or false overrides it for only that session; wrong types reject the request.
4. Authenticate and validate initialize metadata, reserve the ordinary MCP session slot, then request a CDP lease. Pool failure rolls back that admission without consuming `sessionMax`; a later disabled session can still start.
5. Share one allocator across HTTP sessions but create one coordinator, child, lease, proxy, capability, and generation per enabled session.
6. Complete enabled initialize only after Packet 04 readiness and a usable externally advertised `/json/version/` result within the absolute 60-second budget.
7. For `https`, test publication through an operator-style terminator fixture while asserting the bridge listener and Chromium hop remain plaintext.
8. Disabled sessions retain existing lazy-browser behavior and output.

`cloakbrowser_bridge_info` keeps its name and existing fields, gains a complete output schema, and returns a session-local `cdp` value:

- `{ enabled: false }` when the effective session value is false;
- a ready state with generation, bind host, leased port, nullable advertised host, advertised scheme, capability discovery URL, and active connection count;
- an unavailable state defined now and exercised fully in Packet 06.

The raw capability, internal endpoint, Chromium browser/target IDs, and TLS terminator details are never separate fields.
